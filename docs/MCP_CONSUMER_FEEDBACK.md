## ⚠️ `role: "character_cutout"` が透過を保証しない

前回「`character_cutout` は透過PNGだった」と報告しましたが、**全件そうではありませんでした。**

```
character_cutout 81件の内訳: PNG 69件 / JPEG 12件
```

**JPEG はアルファチャンネルを持てない**ので、この12件は透過なしです。

### 実例

`work=301` の唯一の素材 `0301_raw_x4_re.jpg`（3000×1912 / JPEG / mode=RGB）は、
中身を見たところ**切り抜きではなく元絵そのまま**でした。
`EPISODE 0301-1 Landscape` と同じ構図の、より広いクロップです。
名前の `raw` もそれを示しています。

### 何が困るか

利用側が **`role` を見て「透過が使える」と判断できません。**
`role: "character_cutout"` で引いた12件は、重ねると背景が四角く残ります。
いまは1件ずつ実体をダウンロードして確認するしかない状態です。

さらに、この素材に引きずられて実害が出ます。
`EPISODE 0301-1` を**レイヤー分けしてアニメーションさせようとすると、
「キャラの切り抜きがある」と見えるのに実際には無い**、という判断ミスが起きます。

### 提案（どちらでも）

- **`hasAlpha: boolean`（または `format: "png" | "jpg"`）をレコードに足す**
  → 利用側が取得前に弾ける。**これが一番安いと思います**
- `role` の意味を「透過切り抜き」に厳格化し、`raw` な元絵は別ロール（`source` など）に移す

前回書いた「`role: "background"` が欲しい」と根は同じ話で、
**ロールが実体を保証してくれると、取ってから確認する往復が消えます。**

## 参考：デザイン側は形式も置き場所もバラバラでした

問題ではないのですが、利用側の実装で気づいた点として。

| デザイン | `url` の形式 | パス |
|---|---|---|
| `IMAGINE #001` | JPEG 256KB | `/banners/{id}/full/…` |
| `EPISODE 0301-1 Landscape` | **PNG 4.8MB**（RGBA・ただしアルファは全面不透明） | **`/downloads/…`** |

URLをそのまま渡す使い方では困りませんが、
**サイズが20倍違う**ので、base64で埋める経路だと効いてきます
（4.8MB → base64で約6.4MB）。
`fileSize` が `fields` で取れると、事前に見積もれて助かります。
