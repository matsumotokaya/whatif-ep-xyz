## 残課題（新規に見つかったものを含む）

### A. `?w=` / `?ar=` が「無視される」（#6 の続き）

利用側で一番効くのはこれ。**i2v は元画像のアスペクト比がそのまま出力比になる**ため、
16:9 の動画を作るには 16:9 の素材が要る。レンダー済み135件の内訳は
**16:9 が40件** / 4:5 が48 / 9:16 が45 / 1:1 が1 / 40:21 が1。
つまり「この4:5の絵で16:9の動画」ができない。

実装するまでの暫定として、**未対応のクエリは 400 で弾いてほしい。**
いま 200 で原寸が返るので、利用側は「リサイズが効いた」と誤認したまま進んでしまう。

### B. `fields` が「追加」専用で、既定の10項目を削れない

説明文どおりの挙動（"extra fields to **add** to the compact record"）なので仕様どおりだが、
`fields: "id,name,aspect,url"` と指定しても 200件で 17,536 トークン返る。
`docWidth`/`docHeight`/`urlKind`/`stale` は探索フェーズでは不要なことが多い。

**提案**: `fields` に絞り込みの意味も持たせる（指定時はその項目＋`id` だけ返す）か、
`compact: true` のような別引数を足す。id + name + aspect + url だけなら200件で**約6,000トークン**。

### C. `fields` が配列を受け付けない

`fields: ["id","name"]` は
`Invalid input: expected string, received array at fields` で弾かれる。
JSON Schema で `type: "string"` と宣言してあるので仕様どおりだが、
**LLM クライアントは配列を渡しがち**（複数値だから）。
`anyOf: [string, array of string]` にしておくと1往復減る。

### D. タグの大小文字が揺れていて、片方が取りこぼされる

```
tag="Character" -> total=33
tag="character" -> total=1
```

`tag` は case-sensitive と明記されているので API は仕様どおり。**データ側の揺れ**。
`character` の1件は `Character` で検索しても永久に出てこない。
データを寄せるか、マッチを case-insensitive にするかのどちらか。

### E. designs の 61% が未レンダー（210 / 345件）

API の問題ではなく在庫の問題。`renderedOnly` で避けられるようになったので実害は消えたが、
**素材として実際に選べるのは135件**。エディタで開いて保存し直すバッチがあると在庫が一気に増える。

## 検証方法

すべて `https://whatif-ep.xyz/api/mcp` に JSON-RPC を直接 POST して計測（`Accept: application/json, text/event-stream` 必須）。
トークン数はバイト数 ÷ 4 の概算。デプロイ後 2026-09-04 11:00 前後の値。
